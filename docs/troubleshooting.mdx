# Troubleshooting

## The plugin does not load

If `/loadout` is not in the command list, do these steps:

1. Run `claude plugin list` in a shell. Find `loadout@loadout` and check that its status is
   `enabled`.
2. Run `/reload-plugins` in the session, or start a new session.
3. Start Claude Code with `claude --debug`. Find the lines that start with `loadout:`. They give the reason.

## `/loadout` says that the session has no loadout yet

The plugin sets the loadout from the first prompt. Send a prompt, then type `/loadout` again.

## Claude cannot find a tool or a skill

Claude can load each hidden item. Ask Claude to search with ToolSearch for a tool, or with SearchSkills for a skill.

If Claude needs an item for each task, put it on the always-keep list with `/loadout keep <name>`. See
[Always keep an item](./usage.mdx#always-keep-an-item).

If the loadout is wrong for the full task, type `/loadout off`. Then start a new session with a first prompt that names
the full task.

## The session is still large

The plugin changes only the three listings. These parts stay as they are:

- The output of your own SessionStart and SubagentStart hooks. To make it smaller, change the hooks.
- `CLAUDE.md`, memory and the system prompt.
- The tools that Claude Code always loads, which are not deferred.

## See each decision

Set the option `traceFile` to an absolute path. The plugin then writes one JSON line for each decision to this file.
Add this entry to `~/.claude/settings.json`:

```json
{
  "pluginConfigs": {
    "loadout": { "options": { "traceFile": "/tmp/loadout.jsonl" } }
  }
}
```

| `event` | When | Fields |
| --- | --- | --- |
| `listing` | The plugin gets a tool listing or a skill listing | `type`, `isScoped`, `kept`, `alwaysKept`, `hidden` |
| `mcp_instructions` | The plugin gets the MCP server instructions | `where`, `removed` |
| `recall` | The plugin checks a later prompt | `named`, `isNewTask` |
| `effort_pick` | The classifier picks the effort of a prompt | `picked` |
| `effort_change` | A main request goes out with an effort other than the request before it | `from`, `to`, `cacheRead` |
| `effort_frozen` | A request after a change of effort lost most of the cache. The effort stays for the session. | `level`, `model` |

If `isScoped` is `false`, the plugin kept the full listing. These are the causes:

- The plugin did not have the first prompt yet.
- The loadout is off for the session.
- The session has no ToolSearch. This applies to a tool listing only.

The trace contains names and counts only, not the text of your prompts.

## Limits

- The plugin picks the loadout from the first prompt only. A task that changes direction keeps the first loadout.
  Later prompts get notes, but the listings do not change.
- If Claude Code builds a listing before the plugin has the first prompt, that listing is complete. The plugin then
  does not change it, to keep the prompt cache valid.
- The classifier sees only names and short descriptions. A server with an unclear name can be hidden by mistake.
- With `effortPerPrompt` on, the cache can expire before 5 minutes for other causes (for example, a change of the
  system prompt). If this occurs on the request where the effort changes, the plugin keeps that effort for the rest of
  the session.
- The plugin uses the hooks module API of Claude Code. A new Claude Code release can change this API.
