# Usage

You do not run the plugin. It works on each session from the first prompt.

## Write a clear first prompt

The first prompt sets the loadout for the full session. The classifier sees only this prompt and a short list of the
items.

- Name the task and the systems it touches, for example "Find the cause of the 500 errors in Datadog and fix the
  handler".
- If the task will grow, say so in the first prompt, for example "then open a pull request".
- A prompt with only whitespace does not set the loadout. The next prompt does.

The classifier keeps generously. It keeps each item that can help with the task or its next steps.

## Always keep an item

Some skills help with each task, for example a memory skill or a search skill for past sessions. A narrow first
prompt can hide them. A hidden skill still works, but Claude does not see its description, so Claude does not think
to use it. Put these items on the always-keep list. The plugin never hides an item on this list.

To add an item, type its name:

```
/loadout keep kb-search
```

To remove an item, type `/loadout unkeep kb-search`. If a plugin name on the list covers the item, the plugin
name goes off the list too.

To mark items in a list, type `/loadout pick`. A pane opens with two sections: the tool servers and the skills of the
session. Each row shows these items:

- The mark: `●` for an item on the list, `○` for an item that is not on the list.
- The name. A claude.ai connector shows the name of the connector list, for example `claude.ai Slack`.
- The state of the item in this session: `kept` or `hidden`.
- For a server: the number of tools, the tokens of their definitions, and the first tool names. If a connector is
  not logged in, the row shows `not logged in`.
- For a skill: the tokens of its entry and its description.

Type in the filter field to find an item. Press Tab to go to a row, and press Enter to set or clear its mark. Press
Esc to close the pane.

To see the list as text, type `/loadout list`. Each line shows the mark and the state of the item in this session.

A name on the list can be one of these names:

| Name | What the plugin keeps | Example |
| --- | --- | --- |
| A skill name, with or without its plugin | That skill | `retro:recall` or `recall` |
| A plugin name | Each skill of that plugin | `retro` |
| An MCP server name | The tool group and the instructions of that server | `claude-in-chrome` |

The plugin keeps the names from `/loadout keep` and the pane in its own storage in Claude Code. These names stay
for all sessions.

You can also put names in the plugin option `alwaysKeep`, separated by commas. The plugin adds them to the list. Set
the option in `/config`, or in `~/.claude/settings.json`:

```json
{
  "pluginConfigs": {
    "loadout": { "options": { "alwaysKeep": "kb-search, retro" } }
  }
}
```

`/loadout unkeep` and the pane do not change the option. To remove a name of the option, edit your settings.

A change to the list applies from the next session. The session that is open keeps its listings, so the prompt
cache stays valid. If you change the list before the first prompt, the session uses the new list.

## See the loadout

Type `/loadout`. The command shows these lines:

| Line | Meaning |
| --- | --- |
| Always kept | The items that the plugin kept because of the always-keep list |
| Tool groups kept | The servers whose tools stay in the tool listing |
| Tool groups hidden | The servers whose tools the plugin hid |
| Skills kept | The skills that stay in the skill listing |
| Skills hidden | The number of hidden skills |
| Named to later prompts | The hidden items that a note named to Claude after a later prompt |

If the plugin did not classify the tool groups, one line `Tool groups hidden: none` replaces the two tool group lines.
This happens when the session has no ToolSearch or no MCP tools.

The plugin always keeps the deferred tools of Claude Code itself, for example `WebFetch` and `CronCreate`.

## Turn it off for a session

Type `/loadout off`. The next request has the full listings again. Type `/loadout on` to pick a loadout again.

Each switch changes the listings. The next request thus cannot use the prompt cache. Do not switch often.

## Switch the effort or the model for a session

These commands change the setting for the current session only. Your settings do not change.

| Command | Result |
| --- | --- |
| `/loadout effort on` | The plugin picks the effort for each prompt, from the next prompt. |
| `/loadout effort off` | The next prompts use the effort of the session. |
| `/loadout model on` | The plugin picks the model from the first prompt. After the first prompt, this does nothing. |
| `/loadout model off` | The next requests go to the model of the session. The cache is built again one time. |

`/loadout` shows the setting for this session. A new session or `/clear` starts again with your settings. If the
effort is fixed (see above), `/loadout effort off` keeps it, to keep the cache valid.

## Later prompts

The listings do not change after the first request. If a later prompt needs a hidden item, the plugin adds a note
to that prompt only. The note names the item and tells Claude how to load it.

- The plugin names each hidden item one time per session.
- The plugin checks only the prompts that you send. Background notifications and messages from other sessions do
  not get a check.
- The status line shows the named items, for example `pointed to datadog`.

If the plugin does not name an item, Claude can still find it. Claude searches with ToolSearch for a tool, and with
SearchSkills for a skill.

## New task in the same session

The same call also compares a later prompt with your last three prompts. If the prompt starts a different task, a
toast tells you. The toast suggests a new session or `/clear`. Claude does not see it.

A new session gets its own loadout for the new task. Its context also starts small, so each request costs less.

To turn the check off, set the option `newTaskNote` to `false`:

```json
{
  "pluginConfigs": {
    "loadout": { "options": { "newTaskNote": false } }
  }
}
```

## Effort for each prompt

The plugin can lower the effort for a prompt that does not need much thinking. Less thinking costs fewer tokens. To
turn this on, set the option `effortPerPrompt` to `true`:

```json
{
  "pluginConfigs": {
    "loadout": { "options": { "effortPerPrompt": true } }
  }
}
```

For each prompt that you send, the classifier picks a level from `low` to `max`. It reads the prompt and your last
three prompts.

- The plugin never goes above the effort of the session. If the session runs at `medium`, a pick of `max` gives
  `medium`.
- The effort applies to all requests of the turn. Subagents keep their own effort.
- The plugin changes the effort only on models that keep the prompt cache when the effort changes: Sonnet 5.5,
  Opus 5.5, Opus 5, Fable 5.1, Mythos 5.1 and Haiku 5.5. On other models, a change of effort invalidates the full
  cache, so the plugin does not change it.
- If a request after a change loses most of the prompt cache, the plugin keeps the current effort for the rest of the
  session. `/loadout` then shows `Effort: <level> (fixed: ...)`. A pause of more than 5 minutes or a change of model
  also loses the cache. After these, the plugin does not do this check.
- `/loadout` shows the effort of the newest prompt.

## Model for the session

The plugin can suggest a smaller model for a session with a small task. To turn this on, set the option
`modelForSession` to `true`. You can use it together with `effortPerPrompt`.

The classifier reads your first prompt and picks a model. If that model is smaller than the model of the session,
Claude Code asks you before the first request. If you approve, the plugin sends all main requests of the session to
that model. Later prompts can change the effort only.

- The plugin only goes down in this order: Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5. On other models, and on a
  model with a larger context (for example `[1m]`), it does not ask.
- If you close the question, or no one can answer it (a `-p` run), the session keeps its model.
- Subagents keep their own model. A subagent that uses the model of the session runs on the model of the session,
  not on the smaller model.
- If you change the model with `/model` later, or run `/loadout off`, the plugin stops changing the model for the
  rest of the session. This also occurs when Claude Code changes the model itself (a fallback).
- The plugin cannot change the model of the session itself. The status line, `/model` and the system prompt still
  show the model of the session. The footer shows the model that answers, for example `sonnet-5-5 (loadout)`.
  `/loadout` shows it too.

## Cost

The classifier runs on Haiku with low effort.

| When | Calls | Time limit |
| --- | --- | --- |
| First prompt | One call for the tool listing and one call for the skill listing | 10 seconds each |
| A server connects after the first prompt | One call for its tool group | 10 seconds |
| Each later prompt | One call. With `newTaskNote` off, only while hidden items are left to name. | 5 seconds |
| Each prompt, with `effortPerPrompt` on | One more call, at the same time as the other calls | 5 seconds |
| First prompt, with `modelForSession` on | One more call, before the question to you | 5 seconds |

While hidden items are left to name, a later prompt waits for its call. Otherwise the call runs in the background.
If the call fails or reaches its time limit, the prompt continues with no note and no toast.

With `effortPerPrompt` on, the first request of a turn waits for the effort call. If the call fails, the request keeps
the effort of the session.
